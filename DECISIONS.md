# DECISIONS.md — unspecified choices, one line each

- Package manager: npm (repo had no lockfile; npm ships with Node, zero setup).
- Scaffold: manual (not create-next-app) because repo already contained CLAUDE.md/.claude which the CLI refuses; same resulting layout.
- No `.env.local` present at build time → ALL external keys missing; per rule 4 every integration is fully built and only the outermost call is stubbed behind `// TODO(key-needed)` guards (see BUILD_REPORT.md for the list).
- Tailwind v4 tokens: mapped docs/03 §9 CSS vars into `@theme` as `--color-*`/`--radius-*`/`--shadow-*` names so Tailwind utilities (`bg-primary`, `rounded-card`, `shadow-xs`) resolve to spec values.
- Inter loaded via next/font/google with `--font-inter` variable (spec: Inter variable via next/font); JetBrains Mono left as CSS stack fallback (no code-heavy surfaces at launch).
- Typography scale exposed as `.text-h1`-style utility classes in globals.css (docs/03 §2 sizes) rather than Tailwind font-size theme to keep line-height/weight/tracking bundled per spec row.
- Migration split: 0001 is docs/04 §4 verbatim (templates expanded per listed tables); 0002 adds columns screens require but 0001 lacks: profiles.marketing_emails (privacy toggle, 05 §8) and study_plan_items.moved_from ("moved from {day}" note, 05 §7.7 — no column existed for the annotation).
- Doc conflict flagged: 04 §4 says course soft-delete stamps deleted_at on "plan items"/sections/questions, but those tables have no deleted_at column in the schema — children are gated by their parent row instead (comment in lib/trash.ts).
- Soft-delete cascade implemented server-side (admin client) since several child tables are Class B (client can't write them); cascade group = matching timestamp, per 04 §4 restore semantics.
- Realtime private-channel auth implemented as an RLS policy on realtime.messages topics 'job:{materialId|courseId}' (Supabase broadcast-authorization pattern; 04 §8 names the requirement, not the mechanism).
- New-course entry point outside onboarding: dashed dashboard card opens a small name+exam-date modal, then routes to the course's Materials tab with the upload modal open (no dedicated screen specced).
- Course emoji auto-suggest returns 📚 whenever OPENAI_API_KEY is absent or the model reply isn't a bare emoji.
- Uploads metric: every material kind except 'topic' counts toward the 3 free uploads (topic is the "I have nothing yet" escape hatch, not an upload; pasted/YouTube/Quizlet consume real ingestion work so they count).
- Course tab bar mixes views and routes to match doc 04's repo layout: Overview/Notes/Quizzes/Materials are ?tab= views on course home; Flashcards/Tutor/Plan navigate to their own routes (cards/, chat/, plan/).
- Image-only PDFs: doc 04 §9 lists 'ocr_needed→auto-ran' but v1 ships no PDF rasterizer (per-page vision OCR would need one); such PDFs fail honestly as extract_empty with the doc's recovery copy. Standalone image uploads DO run vision OCR.
- Upload progress: real XHR progress for the file transfer (0–40%), then real job-stage broadcasts (extract/chunk/embed) — no fake timers (docs/04 §8).
- Flashcards toolbar hierarchy: "Review {n} due" is the single purple primary (ship-gate rule 2); "New card" and "Generate more" are secondary — docs/05 §7.2 names the controls, not their weights.
- Card delete confirm copy (unspecced): "Delete {n} cards?" + "They move to Trash for 30 days — you can put them back any time." — matches the DS destructive rule (what's deleted + 30-day recovery), red only on the confirm button.
- Bulk-delete undo fans out to one restore('flashcard', id) call per card (lib/trash exposes single-resource restore only); the toast is one "Undo" for the whole selection.
- Cards table due column: "Due now" when fsrs_due <= now, "in {n}h" under 24h, else a short date; suspended rows show "—" (they have no queue position).
- Review summary "on track" = ratings Good or Easy (3–4); Again/Hard are the cards FSRS is still shortening intervals on — docs/05 §7.3 gives the sentence, not the definition.
- Review summary "next session {date}" = earliest new fsrs_due returned by the session's saves, rendered as "later today"/"tomorrow"/short date; the clause is omitted entirely if no save returned a due (never invent a date).
- Esc mid-session confirm (unspecced copy): "End this session?" + "{n} of {m} reviewed. Everything you've rated is already saved." with ghost "Keep reviewing" / secondary "End session" — nothing is destroyed, so nothing in that modal is red.
- Rating-bar next-due previews are computed client-side from previewIntervals() (fuzz enabled) so the bar is instant; the server's scheduleReview result is authoritative for the stored interval.
- Review autosave is fire-and-track, not fire-and-forget: the next card shows immediately, each rating POSTs on its own, failures collect into a red banner with "Retry", and the summary says "Saving your last rating…" until in-flight saves settle.
- reviewCard() takes a 4th optional sessionLengthSoFar argument purely to fill the required session_length_so_far property of the typed card_reviewed event (docs/07 §2.2).
- completeReviewSession(courseId, cards, minutes) added alongside reviewCard so review_session_completed has a caller; it only captures analytics + revalidates (ratings are already persisted).
- cards/ and review/ ship error.tsx using the docs/05 §11 500 copy with "Refresh" (reset) + "Back to course" as the recovery pair — no support URL exists in the app yet, so "Contact support" is omitted rather than faked.
- "Generate more" subscribes to the job:{courseId} realtime channel and refreshes the table on stage 'cards' ready / 'failed' — same real-progress rule as uploads, no polling and no fake timers.
- Build fix (pre-existing, outside this milestone's scope): stripChunkMarkers/extractChunkMarkers moved from the "server-only" lib/ai/rag.ts into pure lib/ai/chunk-markers.ts (re-exported from rag.ts) because client components Markdown.tsx and CitedMarkdown.tsx import them; without this next build fails to compile.
- Quiz + exam share one actions file (quiz/[quizId]/actions.ts) and one presentational module (quiz/[quizId]/QuizShared.tsx) that the exam route imports — docs/05 §7.5 says "same engine", so the shells differ and the engine does not.
- Migration 0003 revokes client select on quiz_questions and re-grants only the quiz_questions_take columns: doc 04 §4's "full quiz_questions reads go through a server action" is unenforceable while the Class B "own read" policy exposes answer/explanation to the anon key.
- Exam integrity in the write path too: during a kind='exam' attempt submitAnswer stores is_correct = null, so even a direct attempt_answers read reveals nothing; every answer is graded inside completeAttempt.
- Short-answer grading = normalized match (lowercase, strip punctuation/smart quotes/articles, collapse whitespace) or the canonical answer appearing verbatim inside a longer response; anything else returns null → the learner self-assesses via selfAssessAnswer(), which rescored the attempt and feeds the flashcard queue on "I missed it".
- Unresolved self-assessments count as neither correct nor a miss: they score as incorrect until answered and never auto-create a flashcard (a card built from an answer the learner may have gotten right is noise).
- startQuizAttempt resumes the newest open attempt for the quiz instead of opening a new one (unlosable-data rule); "Retake" passes { restart: true } to force a fresh attempt.
- Quiz resume jumps to the first unanswered question and has no Back control (one question per screen, reveal is immediate, and every answer resurfaces on the results screen); the exam palette is the only random-access navigation.
- retryQuizGeneration sends the generation event with metered:false — the failed first request already consumed the quizzes_generated quota, and charging twice for one quiz breaks the published-limits promise.
- Misses become flashcards front=prompt / back=answer with the question's source_chunk_ids, deduped on (course, front), inserted with the admin client and never counted in cards_generated (docs/04 §5: only AI generation costs quota).
- Exam "what to reread" insight rows are derived from MISSED questions only (rereading is remediation) and collapse each material's chunk pages into a p.{min}–{max} range.
- Exam auto-add-misses toggle lives in the submit-confirm modal — docs/05 §7.4 attaches it to the per-question feedback card, which exams deliberately don't have.
- Exam submit confirm with zero unanswered uses "Submit your exam?" (docs/05 §7.5 only specifies the unanswered-count copy); the timer auto-submits at 0:00 with a warning toast rather than discarding the attempt.
- Quiz/exam per-topic breakdown groups questions with a null topic under "General" and orders topics worst-first (the weakest topic is the reason the breakdown exists).
- The generating state listens on the job:{courseId} realtime channel (the only quiz-related topic the 0001 broadcast policy authorizes) plus a 5s router.refresh fallback so a dropped socket still lands the user on their questions.
- signup_completed is captured server-side in /auth/callback when the user's created_at and last_sign_in_at are within 10s of each other (first auth); method is read from app_metadata.provider.
- limit_meter_viewed fires from the Meter component itself (once per mount) when it renders at ≤20% remaining, so every metered surface reports it without per-call-site wiring; decorative meters omit the `metric` prop and stay silent.
- error_shown is emitted by a headless <ErrorTracker errorCode> component dropped into error surfaces (route error boundaries use "unhandled_error"; job/ingest surfaces pass their docs/04 §9 code); the imperative reportErrorShown() covers toast paths.
- share_link_created / share_link_opened stay unwired: /s/[slug] sharing is P1 (docs/05 §7, 04 §7 "route reserved") and no shipped surface creates a link. The typed events exist so wiring is a one-liner when P1 lands.
- Ship-gate fix (gate item 10): 10 routes shipped without an error.tsx and 6 without a loading.tsx; added both everywhere via a shared components/ui/RouteError.tsx using the docs/05 §11 500 copy, and hand-matched skeletons per route so there's no layout shift.

- Landing feature-tab crossfade runs as two 100ms halves (fade out → swap → fade in) so only one panel is ever painted — kills StudyFetch's text-overlap bug inside the specced 200ms.

No email inbox is automated; magic-link delivery is covered only by the always-on "link sent" UI copy.

- Seeded usage_counters treat the demo artifacts as ordinary generations (uploads 1, cards 25, quizzes 1, tutor 2) rather than as an onboarding build, so the meters in the demo show real movement; `courses` gets no row because docs/04 §5 defines it as a live count.
- `npm run seed -- --dry-run` prints the full plan including the replayed FSRS state table and writes nothing — the only way to validate the seed on a machine with no Supabase project.
- vitest.config.ts aliases the bare `server-only` specifier to `tests/stubs/server-only.ts`: the package is a Next build-time marker with no Node entry point, and stubbing it is what lets the pure helpers inside rag.ts / guardrails.ts / groundedness.ts be unit-tested without booting Next.
- Vitest `include` is `tests/**/*.test.ts` only, so the Playwright specs (`tests/e2e/*.spec.ts`) can live in the same tree without being picked up by `npm test`; added `test:unit` (tests/unit) and `test:watch` alongside the existing `test` and `eval:ai` scripts.
- BUG FIX (lib/fsrs.ts): `humanInterval` rendered every sub-hour interval with a "<" prefix, so a 30-minute step displayed as "<30m" and a 6-minute step as "<6m". Now anything under ten minutes collapses to the docs/05 §7.3 copy "<10m" and 10–59 minutes shows its real magnitude.
- BUG FIX (lib/ai/rag.ts): `chunkBlocks` carried overlap only while the trailing paragraphs fitted inside the 120-token (15%) target, so any document whose paragraphs exceed ~90 words got ZERO overlap — i.e. every realistic textbook. It now always carries at least the final paragraph (never paragraph 0, so each flush still makes progress) and drops the carry entirely if it would exceed half a chunk.
- BUG FIX (lib/ai/guardrails.ts): the SUSPICIOUS prefilter missed "write me an essay" (the determiner alternation had no slot for the indirect object), so the single most common phrasing of an integrity request skipped the classifier whenever the message also mentioned a course term. The pattern now allows an optional "me"/"us".
- Eval fixtures get deterministic chunk uuids (`{4-hex-prefix}{4-digit-index}-1111-4222-8333-444455556666`) assigned after chunking with the real `chunkBlocks`, so recorded `[chunk:ID]` citations resolve through the production `resolveCitations` path with no database or embedding call.
- The eval golden set is deliberately imperfect — two uncited note sentences and two recorded answer-key failures — so citation coverage lands just above 95% and the answer-key pass rate just above 90% rather than reading a meaningless 100%; a `harness self-checks` block feeds broken artifacts through every metric and asserts each one fails.
- Eval check #3 combines locally computed well-formedness (MCQ answer uniquely among 4 options, no "all of the above", true/false answer boolean, fill_blank has a blank marker and no leak, every explanation carries a resolvable citation) with the recorded/live `{correct, well_formed, explanation_ok}` verdicts; a question passes "first try" only when both agree.
- Eval check #4 runs fully offline: prompt→classifier ROUTING is computed from the real `needsClassifier()` regex prefilter, and only the CHECK-model reply itself is replayed from `redteam.json`. Six on-topic controls assert the prefilter does NOT burn a classifier call on ordinary study questions.
- The "must not appear" falsehood check is refutation-aware: a sentence containing the misconception plus a cue like "not", "assuming", "misconception" or "error" is not flagged, because correct notes quote misconceptions in order to correct them. Regex misconception probes in each `*.expected.json` are the stricter second layer.
- The three golden-set course texts are original prose written for this repo (biology cell structure, US-history Declaration packet, calculus limits/derivatives); the only quoted material is the Declaration of Independence itself, which is public domain. Nothing was downloaded.
- The live eval block is `describe.skipIf(!process.env.OPENAI_API_KEY)` and calls the SAME check functions as the recorded block, so a run with a key added exercises identical assertions against fresh model output; without a key it reports as skipped, never as passed.
- Course-limit paywall opens in place via the hootly:paywall event instead of navigating to /settings?paywall= (the param was never read, so the old path dead-ended — docs/00 rule 1 says limit_hit opens the paywall, never an error).
- createCourse now captures limit_hit {metric:'courses'} — the only limit path that was silently missing its event.
- Refund success is confirmed with a toast keyed off ?refunded=1 (the redirect param existed but nothing surfaced it).
